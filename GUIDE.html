Chrome extension

Burst Clicker

Clicks the Yes button on a page automatically — 1:00 pm Monday–Friday, 10:00 am Saturday–Sunday, every day, on the website's own clock. Turn it on once per tab; nothing to place, nothing to re-arm.

Install

  1. Open chrome://extensions and switch on Developer mode (top right).
  2. Click “Load unpacked” and pick the unzipped burst-clicker folder — the one that contains manifest.json. Keep that folder where it is.
  3. Pin the target icon to the toolbar so you can reach it fast.

Use it — auto-click “Yes”

  1. Open the page that shows the Yes button. Leave it open; it can be in the background or another window.
  2. Toolbar icon → Turn on for this tab. That's it. A pulsing green ring appears around the Yes it will click, labelled with the time. If there's no Yes on screen, an amber notice in the top-right corner says so.
  3. Several lead pages? Open them all, then Toolbar icon → Turn on for every tab with a Yes — one click turns on every tab showing a Yes. A Yes that is disabled until 1 pm gets an amber ring and is clicked the moment it enables.

What it does from then on

At 1 pm on weekdays and 10 am on weekends it finds the visible, enabled button labelled Yes (the top-most one if there are several) and clicks it once. If no Yes is there yet it keeps looking for 3 seconds and clicks the moment one appears. About 20 seconds before, it measures the website's clock and fires on the site's 1 pm, not your computer's. It then arms itself for the next day, and stays on through reloads, navigation and Chrome restarts — until you press Turn off for this tab or close the tab. Test now clicks the Yes on screen in about a second, to check it finds it. Keep the computer awake at those times.

Update

  1. Replace the contents of your burst-clicker folder with the new version's files (same folder, same place), or git pull in it.
  2. chrome://extensions → reload ⟳ on the Burst Clicker card. Tabs that were on arm themselves again.

Markers instead (advanced)

Turn off Auto-click “Yes” and Weekday / weekend schedule in the popup, then:

  1. Open the page you want clicked and get it into the exact state and window size you'll leave it in.
  2. Toolbar icon → Place markers. Click the page wherever a click should fire. Numbered rings appear — a green ring means the marker locked onto the button under it and will follow that button; red means it is a bare coordinate. Drag to nudge, right-click to delete, Esc to exit.
  3. Set “Fire at”. Default is 1:00 pm. Type it however you like — see below.
  4. Set the burst clicks per marker, and the gap between them.
  5. Arm this tab. Repeat on as many tabs as you want, then leave them open and go do something else.

One exact click on a dialog button

The common case: a confirm dialog is open, and its Yes has to be clicked at 1 pm exactly, once.

  1. Open the dialog so the button is on screen.
  2. Place markers → click the middle of the button. The ring turns green: locked to that button, wherever it moves to.
  3. Leave “Lock markers to the element” and “Stop as soon as the click lands” on.
  4. 1 pm (the default) → ⟳ sync to server clock → Arm this tab.

Why the spare clicks are safe

Leave clicks per marker at a few. The first fires on the instant; the rest are only spent if the button is still there. Between clicks the page is asked whether the locked element still exists — the moment it is gone the burst stops, so a retry can never land on the page behind a dialog that just closed.

Getting the click out as early as possible

Everything that does not have to happen at the instant happens before it: ~600 ms out the page resolves every marker to its element, caches it, and sends the hover half of the click; 250 ms out the extension's own panel goes click-through; 60 ms out the page is handed the click and spins to the instant, because hidden-tab timers are throttled to once a second and a spin is not. At the instant there is only pointerdown → mousedown → pointerup → mouseup → click left, on an element the page already holds. Trusted mode parks the cursor early too, and re-resolves the first click's coordinates about 60 ms out — which is what catches a dialog that only opens in the last second.

An exact instant, not a countdown

A countdown accumulates error — every tick that lands a few milliseconds late pushes the end further out, and in a hidden tab a timer can be a whole second coarse.

This never counts down. Arming turns your text into one absolute millisecond, and the wait loop re-reads the system clock on every pass, sleeping most of the way and then busy-spinning the last few milliseconds onto the target. A late wake-up corrects itself instead of compounding. The countdown on screen is only a readout.

Which means

A page reload, a tab shuffle, or Chrome shutting the extension's worker down and restarting it cannot shift the moment it fires. The stored schedule is the instant itself, never “time remaining”.

The field takes whatever is natural and rewrites it to HH:MM:SS.mmm the moment you commit it, so you can see what it understood:

A bare hour with no am/pm is read as 24-hour (1 → 01:00). A time already past today rolls over to tomorrow. Anything unreadable is rejected out loud rather than guessed at.

The fields

FieldWhat it does
Fire atThe exact local instant. Default 1:00 pm.
Clock offsetShifts the target. -150 fires 150 ms early. ⟳ sync to server clock measures it for you: it samples the site's Date header until it ticks over, brackets the moment the server crossed a second, and writes the difference here.
Start delayWaits this long after the target before the first click.
Clicks per markerHow many clicks each marker gets.
Gap between clicksMilliseconds between consecutive clicks. 0 fires them in a single tick.
OrderRound-robin (1,2,3,1,2,3) or per marker (1,1,1,2,2,2).
Keep bursting forRepeats the whole burst for this long — for when the button you want takes a moment to appear.
Gap between roundsPause between repeats while sustaining.
Lock markers to the elementOn by default. The marker remembers the button it was dropped on and clicks wherever that button is at fire time.
Stop as soon as the click landsOn by default, for locked markers. Ends the burst the moment the target is gone.

Total clicks are capped at 5000 per run.

Many tabs, and tabs you can't see

Arm as many tabs as you want. Each schedule is a snapshot taken when you armed it, so editing the fields afterwards only affects the next tab you arm — an armed tab keeps the time it was armed with. The popup's Armed tabs list shows every one with its own countdown and a ✕ to disarm it.

A tab does not need to be focused, on screen, or in the front window. That works because the extension's background worker owns the clock, not the page: Chrome throttles page timers to once a second in a hidden tab, so a page can't be trusted to time its own burst. The worker times everything and drives each tab — dispatching the input itself in trusted mode, or handing the page short chunks it executes by spinning, which throttling doesn't touch.

Verified, not assumed

The test suite arms two off-screen tabs for instants 1.5 s apart, and checks each one reported visibilityState === "hidden" at the moment it clicked. Both landed within 2 ms.

Armed tabs are also protected from Chrome's Memory Saver, so it can't discard them while they wait.

Trusted clicks

Some sites ignore synthetic events and only react to real input. The Trusted clicks toggle dispatches genuine browser input through the DevTools protocol instead, which the page cannot tell apart from your mouse.

Turn it on before placing markers

Chrome shows a “started debugging this browser” banner while attached, and that banner shifts the page down. Markers placed before the banner appears would point slightly off. Enable the toggle first, then place.

How markers behave

A marker remembers two things: the screen position you dropped it on, and — with the lock on — the element that was under it: its selector, its visible text, and where inside its box you clicked. At fire time the click goes wherever that button is now, so a centred dialog that moved because the window was resized, because the DevTools banner appeared, or because it re-rendered, still gets hit. Only if the element cannot be found does the marker fall back to its stored pixel.

With the lock off

A marker is a plain screen position, like a desktop auto-clicker aimed at a spot: it hits whatever ends up underneath. Then don't scroll or resize after placing. Either way markers are remembered per page URL, so a reload is fine — and two tabs on the same URL share the same click points, while still keeping their own separate times.

The extension's own panel turns click-through while a burst is firing, and slides to a clear corner when you arm if a marker sits under it, so it can never eat a click.

If something misses

SymptomCause / fix
Nothing armed after restartChrome reassigns tab ids on restart, so schedules are cleared. Re-arm.
Fired very lateThe Mac slept through the target. Nothing in the browser can fix that — keep it awake.
Schedule vanishedThe tab was closed, or navigated to a different URL. Both cancel it by design.
Clicks land nowhereThe page scrolled or resized after placing. Re-place the markers.
Page ignores the clicksEnable Trusted clicks, then re-place markers.
Consistently early / lateNudge Clock offset by the observed drift.
Fired but nothing was reservedCheck the popup's run log — it lists which element each click actually hit.
